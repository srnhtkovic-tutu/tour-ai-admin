# スポット収集再設計 Phase 1 適用手順（未実施）

## 適用前提

このブランチのSQLとEdge Functionは未適用。テストとレビューが完了するまで本番へ適用しない。

## 安全な適用順序

1. Supabase開発ブランチでマイグレーションを適用し、DB構造とRPCを検証する。
2. 開発ブランチに `merge-spot-information-v3-worker` をデプロイして単体確認する。
3. 開発ブランチに新Dispatcherをデプロイし、`pipeline_version` による経路分岐を確認する。
4. 新規テストジョブが `redesign_v1`、既存ジョブが `legacy_v1` であることを確認する。
5. 正常系・エラー系・停止再開のテスト計画を実施する。
6. テスト結果をレビューしてから本番適用を別途判断する。

## 本番適用時の順序

1. 新しいv3 Workerをデプロイする（Dispatcherから呼ばれるまでは使用されない）。
2. 新Dispatcherをデプロイする。DBにpipeline_versionがまだない場合は、未設定をlegacy_v1として扱う。
3. DBマイグレーションを適用する。既存ジョブはlegacy_v1、新規ジョブはredesign_v1になる。
4. テスト用の新規ジョブを作成し、処理経路・結果を確認する。
5. 問題がないことを確認してから通常運用へ移行する。

## 既存ジョブの保護

- マイグレーション適用時点で存在するジョブはlegacy_v1に固定する。
- 一時停止中の既存ジョブを新設計へ自動変換しない。
- 既存ジョブの再開は旧v2 Workerと旧工程を使う。
- 既存ジョブを新設計へ移す必要がある場合は、対象と再処理範囲を別途確認する。

## ロールバック時の注意

- Cronを停止またはシステム全体を停止してからコードを戻す。
- `redesign_v1` のジョブが残っている間は、旧Dispatcherだけで処理を再開しない。
- DBマイグレーションはデータ保護のため自動で逆戻ししない。必要な場合は状態とデータを確認して個別対応する。
